# Security fix release procedure

These changes are local until the backend functions, web build and native apps are released.

1. Apply `supabase/migrations/20260907120000_password_reset_throttle.sql` before deploying `send-password-reset`. The function deliberately returns HTTP 503 if its rate-limit RPC is missing or unavailable. The table contains SHA-256 email identifiers and timestamps, not recovery tokens. Requests for the same normalized email are limited to one every five minutes. This does not replace infrastructure-level protection against distributed email abuse.
2. Confirm `APPLE_ISSUER_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` and `APPLE_BUNDLE_ID` are set in Supabase. Both production and sandbox purchases now require a successful Apple Server API lookup. The former unsigned client-JWS fallback is removed. `STORE_PRO_PRODUCT_ID`, if set, must match the native app SKU. Development bypass now requires both `STORE_VERIFY_DEV_BYPASS=1` and `DENO_ENV=development`.
3. Deploy the changed functions: `verify-store-purchase`, `confirm-checkout-session`, `stripe-webhook`, `send-password-reset`, and `create-checkout-session`. The Stripe functions share `_shared/checkoutPayment.ts`; deploy both payment handlers to prevent refunded checkout sessions being reactivated by either route.
4. Release the web build, including the security headers in `vercel.json`. Run `npm run cap:sync` with Node 22, then build and submit new Android/iOS releases. Building `dist-capacitor` alone does not update installed apps. Android automatic backup is disabled; explicit encrypted vault backups and account cloud sync remain available.
5. Before submitting native releases, exercise Google/Apple sign-in, passkey enrollment/unlock, background/foreground locking, store purchase and restore on real devices. Test Apple sandbox purchases with the server credentials configured. Exercise the recovery email flow against the configured trusted `PUBLIC_APP_URL`; arbitrary redirect destinations are no longer accepted.

Local validation: `npm test` runs 14 regression tests for encryption failure, category preservation, legacy/v2 backups, malformed backups, excessive KDF work, IndexedDB rollback, account isolation, invalid remote snapshots, forged Apple transactions, refunded Stripe payments and password-reset throttling. External providers and email delivery are mocked in these tests. `npm run build` and `npm run build:capacitor` validate the web and native web bundles; they do not validate native binaries, live Supabase RLS settings, store configuration, or actual transactions.

The synchronization model still uses whole-snapshot last-write-wins. Concurrent offline edits on different devices can conflict. This release adds atomic local replacement and serializes cloud operations within a browser; it does not introduce server-side conflict resolution. TOTP remains a client-side unlock check; it is not an independent encryption factor protecting a stolen vault against someone who already knows the master password.

Apple verification reference: [Get Transaction Info](https://developer.apple.com/documentation/appstoreserverapi/get-transaction-info). Stripe reference: [Checkout Session](https://docs.stripe.com/api/checkout/sessions/object).
